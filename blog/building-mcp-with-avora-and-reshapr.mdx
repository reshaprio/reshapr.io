[Avora](https://avora.dev/) lets you build backend APIs visually, generate their code, and deploy them. With [reShapr](https://reshapr.io/), an open source MCP runtime, those APIs can also become tools that an MCP-compatible client can discover and call.

The connection starts with something Avora already generates: an OpenAPI definition. reShapr reads that definition, uses the deployed backend as its target, and exposes the selected operations through the Model Context Protocol (MCP). Your backend continues to handle the requests and data.

This integration grew out of discussions with the reShapr team at a [Paris JUG event hosted by eXalt](https://www.linkedin.com/posts/ahmed-douss-601712250_java-opensource-mcp-ugcPost-7516402472085778434-GyV1/). The result is a connection built on reShapr’s existing interfaces, with no changes required to reShapr’s source code.

Once the preview is ready, Avora provides two URLs:

| URL | Its role in the integration |
| --- | --- |
| **OpenAPI URL** | Describes the API operations, parameters, and response schemas. |
| **Backend URL** | Points to the running API that reShapr calls when a tool is invoked. |

During setup, reShapr imports the definition and configures the endpoint. During use, requests follow this path:

```text
MCP client → reShapr runtime → Avora backend → backend data
```

The same API handlers serve both REST requests and MCP tool calls. A tool that creates or updates a task changes the data through that existing backend logic.

You can build and edit the logic behind these MCP tools visually in [Avora’s Logic Flow Builder](https://docs.avora.dev/logic-flow-builder). Connect actions for conditions and checks, data transformations, and database operations, then redeploy the backend. reShapr calls that API logic; refresh its configuration when the OpenAPI definition or backend URL changes.

## Choose how to use reShapr

Avora provides three workflows, depending on where you want to configure and run reShapr.

### 1. Create MCP directly in Avora

The managed workflow brings MCP setup into Avora’s deployment window. For workspace owners with MCP access:

1. Deploy the workspace and wait for the preview to be ready.
2. Expand **Turn it into MCP**, choose whether to require an API key, and select **Create MCP**.
3. Copy the MCP URL and, for a protected endpoint, its API key.

Avora calls reShapr’s administration API to import the supported public operations, configure the backend endpoint, and create the Exposition that publishes the MCP service through a gateway. reShapr runs as a separate service, and Avora presents the connection details in the workspace.

The Avora team is evaluating this hosting option with a small group of users. Its long-term availability depends on hosting costs, maintenance, and the demands of operating a shared service as usage grows. The CLI and web-interface options remain available for users who want to manage their own reShapr instance.

### 2. Use the reShapr CLI

For a running reShapr installation, open **Share → Use in reShapr → reShapr CLI** in Avora. The dialog provides an import command with your OpenAPI and backend URLs already filled in.

Sign in to your own reShapr control plane, then run the import command. The example below shows its structure; replace these illustrative addresses with your own:

```bash
reshapr login --server 'https://control.example.com'

reshapr import \
  --url 'https://your-api.example.com/openapi.json' \
  --backendEndpoint 'https://your-api.example.com' \
  --apiKey
```

The backend endpoint option asks the CLI to configure and expose the imported Service. The `--apiKey` option requests a protected MCP endpoint. Save the returned URL and key for your MCP client.

A registered gateway must be running and reachable by that client. If you reimport an existing Service, review its current Plan and security settings, which may be reused. See the [reShapr CLI reference](/docs/references/cli-commands/) for details.

### 3. Configure your own reShapr instance through the web interface

If you prefer a visual setup, open **Share → Use in reShapr → reShapr UI** in Avora and copy the two URLs into your instance’s Quick Start wizard:

1. **Import:** select the remote URL option and paste the OpenAPI URL.
2. **Artifacts:** continue without extra artifacts for this basic example.
3. **Plan:** set the backend URL and review the operations to expose.
4. **Expose:** choose endpoint security, complete setup, and copy the MCP URL from MCP Servers.

The backend stays hosted by Avora. You manage the MCP configuration in your reShapr instance and can return to refine the exposed tools.

For local testing, use the address and published port of that instance’s gateway. The web interface and the reShapr gateway component that serves MCP use different endpoints. The [Web UI Quickstart](/docs/tutorials/web-ui-quickstart/) covers the full workflow, and the [Docker Compose guide](/docs/how-to-guides/docker-compose/) covers installation.

## Connect a client and test a tool

Open MCP Inspector, select **Streamable HTTP**, and enter the generated MCP URL. If the endpoint requires an API key, add it in the `x-reshapr-key` header.

Connect and list the available tools. For the task example, create a sample task, list tasks to find it, mark it as completed using the returned identifier, and read it again. You can then delete the sample task to test the final operation and clean up. This checks that tool discovery and the underlying API work together. Follow reShapr’s [MCP endpoint testing guide](/docs/how-to-guides/test-mcp-endpoint/) for the client setup.

Use sample data for the test: MCP tools can perform the same writes as their API operations. Keep API keys private and share access only with clients you trust. MCP endpoint protection does not change the original API’s authentication.

The Avora preview must stay running. If it expires or stops, calls to its backend stop working. After changing the API or deployment, refresh the corresponding MCP setup before testing again.
